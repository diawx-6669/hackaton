# CampusLens — ТЗ проекта для Claude Code

Хакатон LOCUS Startup Hackathon 2026, кейс №1 «Визуальный профиль университета».
Дедлайн: **19 сентября 2026, 12:00 (Астана, UTC+5)**. Сдаём рабочий сайт + GitHub + README.

## Суть

Веб-сервис: пользователь вводит название университета и **не позже чем через 30 секунд** получает
проверенный визуальный профиль кампуса: фото кампуса, общежитий, аудиторий, библиотек, лабораторий,
спорта, студенческой жизни и города. У каждого фото: кликабельный источник, дата (если есть),
индекс достоверности с объяснением.

Главный принцип: **доверие важнее количества**. 15 проверенных фото лучше 100 случайных.
Если фото не удалось подтвердить — понижаем достоверность или честно пишем, что данных нет.
Уверенно показать чужое фото — худшая ошибка.

Слоган: «Университеты показывают рекламу. CampusLens показывает, как там на самом деле».

## Жёсткие правила

- Все фото ищутся **автоматически**. Никаких захардкоженных или вручную подобранных фото и результатов.
- Никогда не подделывать источники, скорость, индекс достоверности. Стоковые/чужие фото не выдавать за кампус.
- Соблюдать лицензии, robots.txt и условия API. Указывать User-Agent для Wikimedia.
- Секреты только в `.env`. Добавить `.env.example` и `.gitignore`. Никогда не коммитить ключи.
- Коммитить часто, маленькими шагами, понятными сообщениями (жюри смотрит историю Git).
- После каждого шага проверять, что всё запускается. Не оставлять сломанный main.
- LLM не должна придумывать факты: пишет только по найденным текстам и со ссылками.
- Если какие-то страны/источники не поддерживаются — честно показать это в интерфейсе.
- Вести README по ходу работы.

## Стек

- Монорепо: `/web` — Next.js (App Router) + TypeScript + TailwindCSS; `/api` — Python 3.11+ FastAPI.
- Backend: asyncio + httpx (параллельные запросы, таймауты), Playwright только где нужен JS-рендеринг.
- AI: open_clip (или SigLIP) для категорий и эмбеддингов, imagehash (pHash) для дублей,
  LLM Gemini Flash или Groq для описания.
- Данные: Wikidata, Wikimedia Commons API, OpenStreetMap (Overpass, Nominatim), OSRM,
  поисковый API картинок (Google CSE если доступен, иначе Brave Search API / SerpAPI), Mapillary/Flickr.
- Стриминг: SSE из FastAPI в Next.js.
- Кеш: сначала in-memory/файл, позже Redis или Supabase.
- Деплой: web — Vercel, api — Render/Railway. Модель CLIP на CPU может быть медленной —
  обрабатывать миниатюры, ограничивать число кандидатов (~100–150), при необходимости GPU (Modal/HF).

## Пайплайн

1. **Resolve.** `GET /api/resolve?q=` — поиск вуза в Wikidata (wbsearchentities + SPARQL).
   Нечёткий поиск, аббревиатуры, опечатки (КБТУ, KBTU, МГУ). Возвращать: qid, название, альт. названия,
   город, страна, координаты (P625), сайт (P856), категория Commons (P373).
   Несколько кандидатов → вернуть список, фронт показывает «Вы имели в виду…?».
2. **Collect (параллельно, у каждого сборщика свой таймаут, падение одного не ломает профиль).**
   - Commons: файлы из категории вуза (и подкатегорий 1 уровня) + geosearch ~1 км от координат.
     Брать: url, thumb, страница-источник, автор, лицензия, дата, геометка (extmetadata).
   - Сайт вуза: картинки со страниц о кампусе/общежитиях.
   - Поисковый API картинок.
   - Фото с геометками рядом (Mapillary/Flickr).
   - OSM: общежития (building=dormitory), библиотеки, спорткомплексы, объекты рядом, центр города.
   Недоступный источник → пометка в ответе и в UI.
3. **Dedup.** pHash (точные копии) + косинусная близость CLIP-эмбеддингов (похожие).
   Из группы оставлять лучшее: больше разрешение, надёжнее источник.
4. **Classify.** CLIP zero-shot: Кампус, Общежития, Аудитории, Библиотеки, Лаборатории, Спорт,
   Студенческая жизнь, Город + класс «мусор» (логотип, схема, документ, портрет, скриншот).
5. **Confidence Score (0–100) с уликами:**
   - расстояние геометки до кампуса (близко +, далеко сильный −);
   - доверие к домену: официальный сайт > Commons > СМИ > неизвестный; стоковые домены → отклонить;
   - подтверждение: то же фото найдено в нескольких независимых источниках;
   - метаданные: название вуза в подписи/категории/имени файла;
   - уверенность классификатора;
   - свежесть: старше 5 лет → пометка «может быть устаревшим».
   Каждая улика возвращается в ответе (для карточки фото). Формула — в коде и README.
   Зоны: ✅ Проверено / ⚠️ Требует проверки / ❌ Отклонено (с причиной).
   Пустая категория → явное сообщение «подтверждённых фото не найдено».
6. **Describe.** LLM пишет 4–6 предложений о кампусе только по найденным текстам, со ссылками.
7. **Stream.** `GET /api/profile?qid=` — SSE-события этапов: `found`, `dedup`, `rejected`,
   `verified`, `photo`, `summary`, `done` + время. Фото отправлять по мере готовности.
   Общий бюджет ~25 с, после — отдать то, что готово.

## Интерфейс

- Главная: строка поиска + одна фраза ценности. Выбор при неоднозначности.
- Живая воронка: `Найдено 214 → Дубли −61 → Не тот вуз −88 → Стоки −12 → ✅ Проверено 38 · 14,2 с`.
- Профиль: шапка (название, город, сайт, описание со ссылками); галерея по категориям;
  фильтры «Общежитие», «Спорт», «Лаборатории», «Студенческая жизнь»; вкладки
  «Проверено / Требует проверки / Отклонено».
- Карточка фото: большое фото, кликабельный источник, автор, лицензия, дата, категория,
  разбор индекса достоверности.
- Состояния: загрузка, пусто, ошибка, опечатка, источник недоступен. Мобильная версия обязательна.
- Своя аккуратная визуальная система (цвета, типографика, карточки, иконки).

## Порядок работы (строго по приоритету)

1. Скелет монорепо, запуск web и api, README-заготовка. → коммит
2. Resolve через Wikidata + выбор при неоднозначности. → коммит
3. Сборщик Commons + SSE + простая галерея с источниками. Весь путь работает. Первый деплой.
4. Dedup (pHash, затем CLIP) + классификация + фильтры.
5. Confidence Score, три зоны, карточка фото, честные пустые категории.
6. Описание LLM со ссылками.
7. Второй и третий источники, воронка с таймером, кеш.
8. Дополнительно, если есть время:
   - «День студента»: общежитие → дорога на пары (время пешком через OSRM) → аудитории →
     библиотека → спорт → город; пустые сцены показывать честно;
   - карта (Leaflet + OSM) с точками фото и расстоянием до центра;
   - «Жизнь в радиусе 15 минут» по данным OSM;
   - сравнение двух вузов;
   - поиск по смыслу через CLIP («столовая», «бассейн»);
   - «Голос студента»: выжимки из открытых отзывов (главная боль / общежития / нагрузка 1 курса),
     всегда со ссылками и числом отзывов, при малом числе — предупреждение, без ников авторов;
   - Reality Check: официальные фото рядом с независимыми + факты (свежесть, покрытие).
     **Не выводить процент «обмана»** — его нельзя честно посчитать.
9. Проверка: опечатки, маленький вуз, вуз вне демо, падение источника, время ответа.
10. Скрипт оценки качества: по вручную размеченному набору (`/eval`) считать precision/recall.

## Как нас оценивают

Точность и релевантность фото 30% · техническая реализация 25% · удобство интерфейса 20% ·
скорость 15% · масштабируемость 10%. Жюри само вводит разные вузы (в том числе не из демо),
замеряет время, проверяет категории, дубли, источники и поведение при ошибках.
