# CampusLens AI

**Хакатон LOCUS 2026, кейс 1.** Веб-сервис: вводишь название университета — за считанные
секунды получаешь **проверенный визуальный профиль кампуса**: фотографии из открытых
источников с автором, лицензией, кликабельной ссылкой на источник и разбором улик,
по которым выставлен Confidence Score.

Ключевой принцип: **ничего не захардкожено**. В репозитории нет ни одной картинки-заглушки
и ни одного заранее заготовленного результата — всё ищется на лету в Wikidata и Wikimedia
Commons. Если данных нет, сервис так и пишет, а не придумывает.

---

## Статус

| Шаг | Что | Статус |
|-----|-----|--------|
| 1 | `/api/resolve` — поиск вуза через Wikidata (wbsearchentities + SPARQL), нечёткий поиск и синонимы | ✅ готово |

| 6 | Confidence Score с разбором улик | ✅ шесть улик: геотег, домен, привязка к вузу, название в метаданных, свежесть, повтор в источниках |

## Стек

- **Frontend** — Next.js 16 (App Router, React 19) + TailwindCSS 4, TypeScript. Папка `web/`.
- **Backend** — Python 3.11, FastAPI + uvicorn, httpx (async), sse-starlette, rapidfuzz. Папка `api/`.
- **Тесты** — pytest + respx: все внешние API замоканы, тесты не ходят в сеть.

## Архитектура

```
Браузер (web/)
   │  GET /api/resolve?q=КБТУ                → список кандидатов, ambiguous?
   │  GET /api/profile?id=Q1798175  (SSE)    → поток этапов + финальный профиль
   ▼
FastAPI (api/)
   │
   ├─ services/textmatch.py   нормализация, транслитерация, синонимы, нечёткое сравнение
   ├─ services/wikidata.py    wbsearchentities (ru/en/kk) → SPARQL → University
   ├─ services/commons.py     категория P373 (обход подкатегорий) ┐ параллельно
   │                          geosearch в радиусе от координат    ┘ (asyncio)
   ├─ services/dedup.py       склейка одинаковых файлов, слияние источников
   ├─ services/classify.py    категория фото по метаданным + отсев мусора
   ├─ services/evidence.py    улики + Confidence Score + пороги
   ├─ services/cache.py       TTL-кеш: память + файл, переживает рестарт
   └─ pipeline.py             конвейер и генерация SSE-этапов с таймером
```

**Конвейер (`pipeline.py`)**

```
collecting → resolved → found → deduped → classified → rejected → verified → done
```

Каждый этап уходит клиенту отдельным SSE-событием с полем `elapsed_ms` — отсюда живая
воронка и таймер на фронте. Сборщики стартуют одновременно (`asyncio.create_task` +
`asyncio.wait`), общий дедлайн — `CAMPUSLENS_TOTAL_TIMEOUT` (25 с при требовании «до 30»).
Что не успело — отменяется, ответ не блокируется, а причина попадает в `warnings`.

**Confidence Score.** Взвешенная сумма улик, каждая видна в карточке фото:

| Улика | Вес | Что значит |
|-------|-----|-----------|
| Геотег | 0.30 | расстояние от геотега фото до координат кампуса (дальше 3 км → отклоняем) |
| Источник | 0.25 | официальный сайт вуза (1.0) > Commons (0.8) > `.edu` (0.75) > неизвестный (0.3) > сток (0.0 → отклоняем) |
| Привязка к вузу | 0.25 | файл лежит в категории Commons самого вуза, а не просто найден рядом |
| Классификатор | 0.20 | уверенность классификатора в категории |
| Вуз в метаданных | 0.15 | название вуза найдено в имени файла, подписи или категориях Commons |
| Повтор в источниках | 0.10 | одно и то же фото пришло из нескольких сборщиков |
| Свежесть | 0.05 | снимок старше 5 лет помечается как возможно устаревший |

Если сигнала нет (например, у фото нет геотега), он **не подменяется средним значением** —
веса пере-нормируются по имеющимся уликам, а в `evidence.notes` пишется, чего не хватило.

Пороги: `≥ 0.62` → «Проверено», `0.38…0.62` → «⚠️ Требует проверки», ниже → «Отклонено».
Отклонённое фото всегда несёт причину: `not_a_photo`, `stock_domain`, `duplicate`,
`too_far`, `no_license`, `too_small`, `junk_class` (логотип, схема, документ, портрет),
`not_this_university` (ничто не связывает фото с этим вузом) и `low_confidence`.

**Классификация по категориям.** Сейчас работает классификатор по метаданным
(`services/classify.py`): он читает имя файла, подпись и категории Commons на ru/en/kk
и по ним определяет категорию — отдельно ловится мусор из ТЗ (логотипы, гербы, карты,
схемы, дипломы, портреты, скриншоты). Метод честно подписан `category_source: "metadata"`,
а его уверенность ограничена сверху 0.85: эвристика не имеет права быть уверенной
на 100%. CLIP zero-shot станет вторым, более сильным сигналом, а этот останется
дешёвым предварительным фильтром.

## Запуск

Нужны Python 3.11+ и Node.js 20+. Всё поднимается двумя терминалами.

### 0. Окружение

```bash
git clone <repo> && cd hackaton
cp .env.example .env     # ОБЯЗАТЕЛЬНО впиши свой контакт в CAMPUSLENS_USER_AGENT
```

> Wikimedia требует осмысленный `User-Agent` с контактом. С дефолтным значением
> запросы начнут получать 429.

### 1. Бэкенд

```bash
cd api
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Проверка: <http://localhost:8000/api/health> → `{"status":"ok",...}`,
интерактивные доки — <http://localhost:8000/docs>.

### 2. Фронтенд

```bash
cd web
npm install
npm run dev
```

Открыть <http://localhost:3000>. Если бэкенд не на `localhost:8000`, создай `web/.env.local`:

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

### 3. Тесты

```bash
cd api
pip install -r requirements-dev.txt
pytest -q          # 60 тестов, сеть не используется
```

```bash
cd web
npm run lint && npm run build
```

## Тестовый сценарий

1. Открыть <http://localhost:3000>, ввести **`КБТУ`** (или нажать готовый пример).
2. Запрос уходит в Wikidata. Аббревиатура разворачивается в варианты (`КБТУ` → `KBTU` →
   `Kazakh-British Technical University` + транслитерация), поиск идёт по `ru`, `en`, `kk`.
3. Если запрос подошёл нескольким записям — появляется список кандидатов с городом,
   координатами и отметкой, есть ли категория Commons. Выбираем нужный.
4. Дальше идёт живая воронка с секундомером:
   `Вуз определён → Commons: категория… N файлов → Commons: геопоиск… M файлов →
   Найдено → Дубли удалены → Отклонено → Проверено → Готово за X.X с`.
5. В галерее — вкладки **Проверено / ⚠️ Требует проверки / Отклонено**, фильтры по категориям.
6. Нажать **«Показать улики»** на любой карточке: видно расстояние геотега до кампуса,
   доверие к домену, привязку к категории вуза, число источников и итоговый балл.
7. Клик по фото открывает большой просмотр: полный разбор Confidence Score,
   все метаданные и кнопка «Открыть источник» на Commons.
8. Переключатель **«Карта»** показывает кампус и точки фото на OpenStreetMap:
   цвет точки — зона достоверности, в попапе миниатюра, расстояние до кампуса
   и ссылка на источник.
9. Вкладка **«Сравнить вузы»** (`/compare`) — два профиля собираются параллельно,
   в таблице видно, у кого больше подтверждённых фото, выше средний Confidence
   и шире охват категорий.
10. Повторный запрос того же вуза отрабатывает заметно быстрее — работает кеш.
    Его статистику видно в `/api/health`.

Проверки «на честность»:

- логотипы `.svg`, слишком мелкие файлы и файлы без лицензии уходят во вкладку
  **«Отклонено»** с причиной;
- фото с геотегом дальше 3 км от кампуса отклоняется как `too_far`;
- один и тот же файл, найденный и по категории, и по геопоиску, схлопывается
  в один — и получает улику «повтор в источниках»;
- если Wikidata недоступна, сервис пишет «источник не ответил», а **не**
  «такого вуза нет»;
- логотип отличается от фотографии не только по расширению: классификатор
  метит его как «мусор» отдельной причиной `junk_class`;
- фото, найденное только геопоиском и никак не связанное с вузом, отклоняется
  с причиной «не тот вуз», а не с общим «низкий балл»;
- пустая категория объясняет, почему она пустая.

Быстрая проверка API без фронта:

```bash
curl "http://localhost:8000/api/resolve?q=КБТУ" | jq
curl -N "http://localhost:8000/api/profile?q=Nazarbayev%20University"   # SSE-поток
curl "http://localhost:8000/api/profile.json?id=Q1798175" | jq '.stats' # тот же конвейер одним ответом
```

## API

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/health` | health-check |
| `GET` | `/api/resolve?q=&limit=` | кандидаты-вузы из Wikidata, флаг `ambiguous` |
| `GET` | `/api/profile?q=` или `?id=Q…` | **SSE**: поток этапов, последнее событие `done` несёт профиль |
| `GET` | `/api/profile.json?q=` или `?id=Q…` | тот же конвейер одним JSON-ответом (для curl и тестов) |
| `GET` | `/api/compare?a=&b=` (или `a_id`/`b_id`) | сравнение двух вузов, оба профиля собираются параллельно |

Параметр `qid` поддерживается как синоним `id` — в ТЗ эндпоинт описан именно так.

**Страницы сайта:** `/` — поиск и лендинг, `/u/<QID>` — постоянная ссылка на профиль
(её можно отправить, она пересоберёт профиль сама), `/compare` — сравнение двух вузов.

## Источники данных

- **[Wikidata](https://www.wikidata.org)** — `wbsearchentities` (поиск по названиям и алиасам
  на ru/en/kk) и SPARQL-эндпоинт `query.wikidata.org`. Берём: QID, название, описание,
  город (P131), страна (P17), координаты (P625), официальный сайт (P856),
  категория Commons (P373), логотип (P154), дата основания (P571).
  Тип сущности проверяется обходом `P31/P279*` до «учебного заведения» — чтобы в выдачу
  не попадали одноимённые компании и станции метро. Данные Wikidata — CC0.
- **[Wikimedia Commons](https://commons.wikimedia.org)** — `list=categorymembers`
  (обход категории вуза и подкатегорий), `list=geosearch` (файлы с геотегом в радиусе),
  `prop=imageinfo|coordinates` c `extmetadata` для автора, лицензии, даты и GPS.
  Лицензия каждого файла своя и показана в карточке.

Оба API — публичные, ключи не нужны. Опциональные источники шага 8 (Brave Search / SerpAPI /
LLM) требуют ключей и читаются только из `.env`.

## AI и внешние API

- **Wikidata Query Service (SPARQL)** — метаданные вуза.
- **MediaWiki API (Commons)** — поиск и метаданные файлов.
- **rapidfuzz** — нечёткое сопоставление запроса с названиями и алиасами, сравнение
  аббревиатуры с инициалами названия.
- **Классификатор по метаданным** (свой, `services/classify.py`) — категория фото
  по имени файла, подписи и категориям Commons; он же отсекает мусор.
  Это правила, а не модель.
- **imagehash (pHash)** — перцептивная дедупликация по миниатюрам. Классический алгоритм.
- **OpenStreetMap + Leaflet** — карта кампуса с точками фото.
- **CLIP / SigLIP zero-shot** (шаг 5, планируется) — классификация по пикселям
  и более надёжный отсев «мусора».
- **LLM-описание кампуса** (шаг 6) — Claude через официальный SDK `anthropic`, модель
  задаётся в `CAMPUSLENS_LLM_MODEL` (по умолчанию `claude-opus-5`). Работает только
  при заданном `ANTHROPIC_API_KEY`; без ключа описание просто не появляется.

> **Как мы не даём LLM выдумывать.** В модель уходит пронумерованный список фактов,
> собранных нашим же конвейером, и ничего больше — ни общих знаний, ни веб-поиска.
> Ответ приходит структурированным: текст плюс список утверждений с идентификатором
> источника. Каждую ссылку сервис проверяет на своей стороне: утверждение,
> сославшееся на источник, которого мы не давали, отбрасывается и в текст не попадает,
> а в профиль пишется, сколько таких утверждений было. Если подтверждённых утверждений
> не осталось, описание помечается как недостаточное и не показывается.

> **Где в проекте по-прежнему нет ИИ.** Категории фото определяет поиск ключевых слов
> по метаданным, а не нейросеть: CLIP не подключён (причины — в ограничениях).
> Похожесть названий — rapidfuzz, дубли — перцептивный хеш. Это классические алгоритмы.

> **Использование AI-ассистента.** Код этого репозитория написан при активном участии
> AI-ассистента (Claude Code): архитектура, реализация бэкенда и фронтенда, тесты
> и документация создавались в паре с моделью, вся логика проверялась и запускалась
> вручную. Сам сервис при этом не генерирует изображения и не выдумывает данные —
> он только ищет, фильтрует и объясняет то, что нашёл в открытых источниках.

## Ограничения (честно)

- **Классификация идёт по метаданным, а не по пикселям.** Если у файла бессмысленное
  имя (`IMG_0042.jpg`) и нет категорий, он останется без категории. Фото, подписанное
  «общежитие», но снятое не там, классификатор не поймает — это работа для CLIP (шаг 5).
  Метод везде подписан `category_source: "metadata"`, за CLIP мы его не выдаём.
- **Сравнение CLIP-эмбеддингов не реализовано** (шаг 4). pHash ловит тот же кадр в другом
  размере или под другим именем, но два разных снимка одного здания с разных ракурсов
  остаются двумя карточками — для этого нужны эмбеддинги.
- **Категории фото определяет не нейросеть, а правила.** CLIP не подключён (причина ниже),
  поэтому категория выводится из имени файла, подписи и категорий Commons. Метод везде
  подписан `category_source: "metadata"`. Единственная модель в сервисе — LLM, которая
  пишет описание кампуса, и то лишь при заданном ключе.
- **Почему нет CLIP.** Веса модели (~350 МБ) и torch (~554 МБ) не помещаются в 512 МБ RAM
  бесплатного и стартового тарифов Render. Нужен инстанс от 2 ГБ либо вынос модели
  в отдельный сервис (Modal, HF Spaces). Выдавать классификатор по метаданным за CLIP
  мы не стали: он везде подписан `category_source: "metadata"`.
- **Основной источник — Wikimedia.** Качество профиля напрямую зависит от того,
  насколько вуз описан в Wikidata: без координат (P625) не работает геопоиск и геоулики,
  без категории Commons (P373) остаётся только геопоиск. Сервис явно предупреждает об этом
  в `warnings`.
- **Геопоиск ловит город, а не только кампус.** В радиусе 1 км попадают соседние здания
  и городские виды; их отсеивает Confidence Score, но точность вырастет после классификатора.
- **Кеш живёт на диске контейнера.** На бесплатных тарифах Render/Railway диск
  эфемерный: после передеплоя кеш пуст. Redis/Supabase — следующий шаг.
- **Сравнение вузов — про объём и качество найденных данных, а не оценка самого вуза.**
  «Больше подтверждённых фото» значит только то, что вуз лучше описан в открытых
  источниках. В интерфейсе это написано прямо под таблицей.
- **Таймаут 25 с** — жёсткий. У вузов с огромными категориями Commons часть файлов может
  не успеть догрузиться; это видно в `warnings`.
- **Rate limits.** Wikimedia режет анонимные запросы, поэтому `CAMPUSLENS_USER_AGENT`
  с контактом обязателен.
- **Сеть обязательна.** Сервис не работает офлайн и не имеет офлайн-заглушек — это
  осознанное решение, чтобы демо никогда не показывало фейковые данные.
- **Замер точности (precision/recall) ещё не проведён.** В ТЗ он есть (п.10),
  размеченного набора `/eval` пока нет, и придумывать цифры мы не станем.

## Секреты

Ключей для базовой работы не требуется. Всё, что появится (Brave Search, SerpAPI,
LLM), читается только из `.env`, который добавлен в `.gitignore`. В репозитории лежит
лишь `.env.example` с пустыми значениями.
